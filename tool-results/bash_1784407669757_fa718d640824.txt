Adaptation Notes — Restaurant Template → Pressure Washing (internal
only)

This section is for your eyes only — remove before handing to lavadoatp
or any other client. These are the domain-specific decisions made
converting the restaurant v3 template to a pressure-washing /
power-washing service business, and why.

+-----------------------------------------------------------------------+
| ADAPTATION 1 — Menu → Services catalog                                |
|                                                                       |
| Pressure washing has no single "menu." Replaced with a service        |
| catalog (Residential / Commercial / Specialty categories) supporting  |
| three pricing models — fixed, starting-at, and quote-only — because   |
| most jobs in this trade are priced by surface area and condition, not |
| a flat menu price.                                                    |
|                                                                       |
| ADAPTATION 2 — Reservations → Bookings & Crew Scheduling              |
|                                                                       |
| There is no seating or floor plan in this business. The               |
| floor-plan/table-assignment UI was replaced with a calendar-grid job  |
| scheduler plus a crew-assignment field, since the operational unit is |
| a scheduled on-site job, not a seated table.                          |
|                                                                       |
| ADAPTATION 3 — Before/After Slider promoted to a first-class          |
| component                                                             |
|                                                                       |
| Before/after transformation is this industry's single                 |
| highest-converting asset — arguably more than for restaurants, where  |
| a photo gallery is closer to atmosphere-setting than proof-of-work. A |
| dedicated drag-slider component, paired and sourced from the same     |
| job's real Instagram content, now gets its own Step 3 subsection      |
| instead of being folded into a generic gallery.                       |
|                                                                       |
| ADAPTATION 4 — Video is treated as mandatory, not optional            |
|                                                                       |
| Pressure washing sells through motion — the "oddly satisfying"        |
| transformation clip is the format that actually drives engagement in  |
| this niche. The Instagram scrape pipeline (Step 0A) was extended to   |
| pull Reels/video, not just static images, and a zero-video result is  |
| logged as a launch-blocking data gap, not a cosmetic one.             |
|                                                                       |
| ADAPTATION 5 — Zero-AI-media rule extended to video, and to           |
| before/after authenticity specifically                                |
|                                                                       |
| Stock or AI-generated imagery undermines trust on any local-service   |
| site, but a faked or digitally "enhanced" before/after pair is close  |
| to consumer-fraud territory in this specific trade — operators have   |
| been called out publicly for staged before/afters. This prompt treats |
| real, same-job, unedited pairs as a hard requirement, not a style     |
| preference, and removes the restaurant template's Unsplash            |
| stock-photo fallback entirely (see Step 3.1).                         |
|                                                                       |
| ADAPTATION 6 — Location → Service Area                                |
|                                                                       |
| Many pressure-washing operators run mobile crews across a metro       |
| radius rather than a single storefront. The schema and the location   |
| section now support a zone/radius coverage model in addition to (or   |
| instead of) a fixed address.                                          |
|                                                                       |
| ADAPTATION 7 — Schema.org type changed                                |
|                                                                       |
| Restaurant → HomeAndConstructionBusiness, with an areaServed property |
| — the accurate, validator-recognized type for this trade.             |
|                                                                       |
| ADAPTATION 8 — Quote Calculator moved into Phase 1                    |
|                                                                       |
| An instant ballpark estimate (service type + property size → price    |
| range) is close to an industry-standard conversion tool for           |
| pressure-washing sites, unlike restaurants, where there's no real     |
| equivalent. Built now, not flagged as a Phase 2 upsell.               |
|                                                                       |
| WHATSAPP WIDGET — deliberately left unchanged                         |
|                                                                       |
| The v3 spec (Step 3.2) already followed the correct pattern: a real   |
| wa.me click-to-chat button, not a custom fake chat UI pretending to   |
| be WhatsApp. Nothing about pricing or scheduling logic changes that.  |
| Only the pre-filled greeting text was reworded for a quote-request    |
| context — mechanically, it is the same widget.                        |

3. Usage Notes

-   One business = two inputs. Company Name + Instagram URL. That is the
    entire workflow per client.

-   Library: save each filled version as "[CompanyName]_v1.md" — track
    what was scraped vs. manually supplied.

-   Default admin credentials: owner email = first staff invite. No
    shared passwords. Owner sets their own password via Supabase email
    invite.

-   Supabase free tier: 500MB DB + 2GB storage + 50,000 MAU — covers a
    single business indefinitely at demo and early-live scale. Video
    storage is the constraint to watch, not rows — budget accordingly
    once Reels are in play.

-   Phase 2 pitch: after the site is live and the owner sees the admin
    portal working, pitch recurring maintenance plans and crew dispatch
    as a monthly SaaS retainer — the database is already structured for
    it.

-   Instagram re-sync: owner can click "Re-sync from Instagram" in Admin
    → Site Editor at any time to pull new photos and video without a
    redeploy.

-   Bolivia-specific: currency defaults to BOB. Default service area:
    Santa Cruz de la Sierra metro + configurable radius, editable in
    Admin → Settings once the real address/zones are confirmed from the
    scrape. WhatsApp is the primary conversion channel — not email.
